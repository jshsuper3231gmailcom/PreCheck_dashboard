01

공통 규칙

Common Rules
[서버구분][LOG_ID][입력타입][...타입별 추가 필드...]
서버구분 — collect/analyze 스케줄의 서버ID와 동일 문자열 LOG_ID — 정규화 로그의 LOG_ID(가이드1 참조) 입력타입 — 문구/수치/날짜/존재/정보/비교/시간

주석 처리

라인 시작에 #를 붙이면 해당 라인은 무시됩니다.

#[dlprem01-테스트개발][DISK_HOME][수치][<][90][20]

중복 라인 — 마지막이 최종 적용

동일 서버구분+LOG_ID 조합이 파일에 여러 번 나오면 마지막 라인의 값으로 덮어써집니다(먼저 나온 정의는 무시).

정책 미등록 LOG_ID

수집은 됐지만 정책이 없는 서버구분+LOG_ID는 ANALYZE_LEVEL='미분석'으로 저장되고, notify(SMS) 통보 대상에서 제외됩니다.

정책 변경 적용

정책 파일은 analyze 서버 기동 시 1회만 로딩됩니다(@PostConstruct). 운영 중 파일을 수정해도 analyze 서버 재기동 전까지는 반영되지 않습니다.

서버구분 ≠ 입력타입 매칭
정책 조회 키는 서버구분:LOG_ID 뿐이며 입력타입은 키에 포함되지 않습니다. 정책의 입력타입은 실제 수집 로그의 LOG_TYPE과 반드시 일치해야 합니다 — 다르면(예: 로그는 "수치"로 수집됐는데 정책은 "문구"로 등록) 해당 로그 분석 중 예외가 발생합니다.

에러 키워드 매칭

에러키워드콤마 구분, content에 하나라도 부분 포함되면 에러
미포함정상
[dlprem01-테스트개발][SYS_MSG][수치] ← 오타 아님, 아래가 실제 형식 [dlprem01-테스트개발][SYS_MSG][문구][오류,Exception,error,ERROR,실패] [pamoap01-자동주문][DB_CONN_STATUS][문구][error,Error,failed,timeout,오류] [pjpsap01-주파수클럽][PUSH_STATUS][문구][실패,denied,refused]
키워드는 부분 문자열 포함 검사
정규식이 아니라 content.contains(키워드) 방식입니다. 로그 문구가 "PUSH 전송 실패없음"이면 "실패없음"이라는 의도와 무관하게 "실패"가 그대로 포함되어 에러로 판정됩니다 — 정책 쪽에서 고칠 방법은 없고, 대상 서버의 로그 문구 자체를 키워드와 겹치지 않게 남기는 것이 유일한 해결책입니다.
수치

임계치 비교 + 경고 근접 판정

[서버구분][LOG_ID][수치][연산자][임계치][경고근접비율%]
연산자>, >=, <, <=, =
임계치비교 기준값(정수/실수)
경고근접비율임계치 대비 경고 판정 폭(%). 정상 조건을 만족한 값 중 임계치에 가까운 구간을 경고로 낮춤. 0이면 경고 구간 없음
경고 구간은 항상 "정상 쪽"에서 임계치에 가까운 영역
조건을 만족하지 못하면(예: <인데 임계치 이상) 무조건 즉시 에러이며 경고로 완화되지 않습니다. 경고는 "조건은 만족했지만 여유폭(경고근접비율%)이 얼마 안 남은" 값에만 붙습니다. 연산자 방향에 따라 경고 구간이 임계치의 아래쪽(<)에 있는지 위쪽(>)에 있는지가 달라지므로 반드시 실제 값으로 검산하세요.
예시 1 — DISK_HOME 수치 < 90 20 (임계치 90, 경고폭 20% → 18)
정상 (< 72)
경고 [72, 90)
에러 (≥ 90)
예시 2 — PROC_MIN 수치 > 5 20 (임계치 5, 경고폭 20% → 1)
에러 (≤ 5)
경고 (5, 6]
정상 (> 6)

">" 연산자는 "값이 클수록 정상"이므로 정상 구간이 임계치 위쪽에 있고, 경고 구간도 그 정상 구간 안에서 임계치에 가장 가까운 위쪽 폭에 생깁니다. "<"는 그 반대(정상·경고 구간 모두 임계치 아래쪽)입니다.

= 연산자 (경고 구간 없음)
[pamoap01-자동주문][MCAST_FLAG][수치][=][1][0] [dcoodb01-주문체결][JCM_BATCHK][수치][=][0][0]
해석
값이 정확히 일치 → 정상 그 외 모든 값 → 즉시 에러 (경고 없음)
예시 3 — QUEUE_SIZE 수치 >= 100 10 (임계치 100, 경고폭 10% → 10)
에러 (< 100)
경고 [100, 110]
정상 (> 110)
예시 4 — SESSION_CNT 수치 <= 500 10 (임계치 500, 경고폭 10% → 50)
정상 (< 450)
경고 [450, 500]
에러 (> 500)

>=/<=는 등호가 있는 만큼 경고 구간이 임계치 자체를 포함합니다 — >=는 임계치보다 작으면 즉시 에러이고 임계치~임계치+경고폭 구간이 경고, <=는 그 반대(임계치 초과가 에러, 임계치-경고폭~임계치가 경고)입니다. 등호 없는 >/<(예시 1·2)와는 경계값 포함 여부와 경고 구간 위치가 달라지므로 혼동하지 마세요.

비교

두 수치 비교 — 대칭모드

[서버구분][LOG_ID][비교][허용값%(선택)]
허용값%(선택) B(두 번째 값) 대비 |A-B| 허용 비율. 생략 시 0(=허용 없음, 불일치 즉시 에러)
정상A == B
경고A≠B, |A-B| ≤ B × 허용값/100
에러A≠B, 허용범위 초과 또는 허용값 미설정
실제 등록 예시
[dcoodb01-주문체결][JUCHE_DIFF_8][비교][5] [pjpsap01-주파수클럽][FREQ_CLUB_COUNT1][비교][5]
해석 (허용값 5%)
A=1000, B=1000 → 일치, 정상 A=980, B=1000 → 차이 20 ≤ 50(=1000×5%) → 경고 A=900, B=1000 → 차이 100 > 50 → 에러
비교

두 수치 비교 — 연산자모드(2026-08-06 신설)

[서버구분][LOG_ID][비교][연산자][허용오차%]

A==B 완전일치가 아니어도 B 대비 일정 비율 이내로 낮거나(또는 높거나) 하면 정상으로 보고 싶을 때 사용. 경고 단계 없이 정상/에러 2단계로만 판정하며, B(두 번째 값)를 매 로그마다 동적 임계치로 사용합니다.

연산자>, >=, <, <= (=는 미지원 — 완전일치가 필요하면 대칭모드 사용)
허용오차%B 대비 허용 오차 비율(%). 0이면 A op B를 그대로 판정(오차 없음)
판정식 (delta = B × 허용오차% / 100)
>=: A ≥ B−delta    >: A > B−delta    <=: A ≤ B+delta    <: A < B+delta   → 충족하면 정상, 아니면 에러
핵심 개념 — B를 재계산한 뒤 원래 연산자를 그대로 적용
허용오차는 A와 B의 차이를 양방향으로 봐주는 밴드가 아닙니다. >=/>는 B' = B − delta(하한만 낮춤), <=/<는 B' = B + delta(상한만 높임)로 새 기준값 B'를 먼저 만든 다음, 그 B'에 원래 연산자를 그대로 적용하는 방식입니다. 연산자가 원래 정상으로 보는 방향의 반대쪽 경계만 완화되는 단방향 조정이라, |A-B|<=오차처럼 양쪽으로 밴드를 두는 대칭모드와는 근본적으로 다릅니다.
비교

연산자모드 예시 A — [비교][>=][5]

B의 95% 이상이면 정상, 상한 없음
에러 (A < B×0.95)
정상 (A ≥ B×0.95, 상한 없음)
실제 등록 예시
[dlprem01-테스트개발][JUCHE_DIFF_03][비교][>=][5]
해석 (B=100 기준, 컷오프=95)
A=99 → 99≥95 → 정상 A=95 → 95≥95 → 정상 (경계값 포함) A=94 → 94<95 → 에러 A=105 → 105≥95 → 정상 (상한 없음)

B가 로그마다 실제로 바뀌면 컷오프도 같이 움직입니다 — 예) 수신$190$ 처리$200$는 컷오프 190이라 정상, 수신$189$ 처리$200$는 에러.

비교

연산자모드 예시 B — [비교][<=][2]

B의 102% 이하면 정상, 하한 없음
정상 (A ≤ B×1.02, 하한 없음)
에러 (A > B×1.02)
실제 등록 예시 — DISK_YEST_DIFF(전일대비)
[dlprem01-테스트개발][DISK_YEST_DIFF][비교][<=][2]
해석 — 로그 $454$$456$ (A=454, B=456)
delta = 456×2% = 9.12 컷오프 = 456+9.12 = 465.12 A=454 ≤ 465.12 → 정상 같은 로그를 [비교][>=][2]로 등록했다면 컷오프 = 456-9.12 = 446.88 A=454 ≥ 446.88 → 정상 (완화 방향만 반대로 바뀜)
시간

임계치 시간 비교(분 단위) · 경고 없음

[서버구분][LOG_ID][시간][연산자][HH:mm]
연산자>, >=, <, <= 만 지원 (= 미지원)
임계치시간HH:mm 형식, 분(minute) 단위로 환산 후 비교
경고 레벨 없음 — 조건 만족은 정상, 불만족은 에러 둘 중 하나로만 판정됩니다.
실제 등록 예시
[pjpsap01-주파수클럽][CHEK_TIME][시간][<=][08:10] [dcoodb01-주문체결][MOMRV_H_1][시간][<=][07:25] [dlprem01-테스트개발][DATE_BTIME][시간][<][08:00]
해석 (CHEK_TIME <= 08:10, 490분)
$07:35$ = 455분 < 490분 → 정상 $08:10$ = 490분 = 490분 → 정상 (<= 이므로 경계값 포함) $09:10$ = 550분 > 490분 → 에러 동일 임계치를 [<][08:10]로 등록했다면 $08:10$ = 490분은 490 < 490이 거짓이라 → 에러 (등호 유무 하나로 경계값의 판정이 뒤집힘)

주의사항

Common Mistakes

운영 중 변경 시 재기동 필수

정책 파일 수정 후 analyze 서버를 재기동해야 반영됩니다. 서버 안 내리고 파일만 바꾸면 이전 정책이 계속 적용됩니다.

수치형 연산자 방향 주의

연산자 방향(</>)에 따라 경고 구간이 임계치의 아래쪽/위쪽 중 어디에 생기는지가 달라집니다. 위 02번 예시로 직접 검산하세요.

서버별 다른 임계치 적용 가능

동일 LOG_ID라도 서버구분이 다르면(예: DISK_HOME이 여러 서버에 공통 존재) 서버마다 별도 임계치를 설정할 수 있습니다.

시간형에 = 연산자 사용 금지

시간형은 >, >=, <, <= 만 지원합니다. =를 쓰면 파싱 실패로 해당 라인이 무시됩니다.

비교형 연산자모드는 경고 없음

비교형에 연산자를 쓰면(5토큰) 시간형처럼 정상/에러 2단계로만 판정됩니다. 경고 등급이 필요하면 연산자를 빼고 대칭모드(3~4토큰)를 쓰세요.

비교형 연산자모드 허용오차는 양방향이 아님

대칭모드의 |A-B|<=오차와 헷갈리기 쉽지만, 연산자모드는 B를 한쪽으로만 재계산(>=/>는 하한만, <=/<는 상한만 완화)합니다. "오차만큼 위아래로 다 봐준다"고 오해하면 실제 판정과 어긋납니다.

문구형 키워드는 정규식이 아니라 부분 포함 검사

"실패없음"처럼 부정 표현 안에 에러 키워드가 그대로 들어 있으면 정책이 아니라 로그 문구 자체를 손봐야 합니다. 정책에서 키워드를 정교화할 방법은 없습니다(단순 contains).
